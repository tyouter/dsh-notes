# 写作伙伴 · 会客厅（需求与分期）

> 2026-11-10 口述整理，是这一路迭代的**过程记录**。
> 结构化的需求、进度、问题与设计已经移到 [`dev/`](dev/README.md)：新接手从这里开始。本文件保留当时的判断与决策脉络。


## 一句话

把写作伙伴从「开麦时手动挑一个人」升级成**一个会自动选人、会造人、还能组局的会客厅**；
开关与人格库管理从写作页移到**插件配置页**。

## 决策（已确认）

| 问题 | 结论 |
| --- | --- |
| 「otto」 | 即 **auto（自动）** |
| 写作页 | 不再放下拉选择，也不再放管理按钮 |
| 手动选择 | 保留，但挪到插件配置页 |
| 默认模式 | **auto**（P1 已实现自动选人） |
| 自动造人 | **直接落库**，不再先问（2026-11-10 改） |
| 引用块 | **标准 Markdown 引用**：`> **名字**：内容` |
| 同时在座 | **最多 3 位**（`maxGuests: 3`） |
| 常驻嘉宾 | **没有特殊含义**——存进人格库就等于在场，不另设 resident |
| 触发时机 | **只在口述停顿**，打字不触发 |

## 人物卡（统一 schema）

```json
{
  "id": "huang-renyu",
  "name": "黄仁宇",
  "nameEn": "Ray Huang",
  "domain": ["历史", "财政", "明代"],
  "brief": "它关注什么、怎么说话（≤800 字）",
  "welcome": "第一次入座时的第一句话（≤120 字）",
  "origin": "preset | custom | auto"
}
```

预设仍在代码（`lib/personas.js` 的 `BUILTIN_PERSONAS`）；自建与自动生成的落 `notes-vault/personas.json`。

  "mode": "auto",

  "maxGuests": 1

## 调校（2026-11-10 晚，试听后）

第一版试听暴露三件事，已修：

1. **换人太勤**：原来每段话都重新选人，于是乔布斯说完换亚里士多德、下一段又换回来。
   现在**一桌到底**——只有空桌才重新选人；新入座的人从入座那一刻开始计冷却。
2. **时机不对**：新客一入座就开口；同一次停顿里最多 3 条一起砸下来。现在四道闸：
   每次停顿最多 1 条、两句话之间至少 25s、同一位至少要看到 220 个新字、只在句末（。！？…）插话；
   口述不等模型（插话是后台任务）。
3. **没那味**：提问全是「你是想 A 还是 B」「刚说 X 是什么意思」这类元问题。重写了 prompt：
   禁止谈对话本身、必须落在具体的词/判断/例子上；四个预设的 brief 也加了「怎么说话」。

## 召唤师（2026-11-10 晚，重构）

作者委托的不是"选人器"，而是一位**召唤师**：他负责这场会客厅的全部调度。`/notes/api/voice/convene`
每次返回一份计划，面板照单执行，不再自己猜规则：

```json
{
  "mode": "reply | discuss | listen",
  "timing": "now | pause",
  "seat": [{ "id": "jobs", "directive": "这次只做哪一件事" }],
  "create": null,
  "note": "给作者看的一句调度"
}
```

- **mode**：`reply` 一个人答；`discuss` 几个人互相接话（第二位的差事写明"接谁的话"）；
  `listen` 谁都不开口。
- **timing**：作者说"现在/马上/你来说/你们讨论" → `now`（跳过等待与字数闸门）；
  作者只是在写 → `pause`。**没有请求却要 now 的，会被校验器降级回 pause**。
- **directive**：召唤师给每个人的差事，直接进插话提示词，优先级高于平时的人设习惯。
  reply 只留一份差事；discuss 才给多人写差的、并写清谁接谁。
- **create**：名单里没有合适的人时，召唤师点名要请谁，由 `createPersona` 按统一 schema 写卡落库。

面板只决定**什么时候值得问召唤师**（空桌、作者在对屋里说话、五分钟没看过），其余全部听计划。
`discuss` 时后一位会看到前一位刚说的话，并要求"接住/反驳"，不是各说各的。

### 2026-11-10 晚：改成每停顿都问

原来"空桌 / 被点名 / 5 分钟过期"才问；现在**每次说完、每次长停顿都问**——笔记上下文短，一次调度
输入不过一两千 token，比一个错误的旧计划便宜。召唤师可以回答 `{"keep":true}`，面板沿用上一份计划。

为缓存做的两件事：
- **稳定前缀**：规则、卡格式、名单全在 system；在座、上一份差事、新写的文字全在 user。
  两次调用的 system 逐字相同，只变尾部。
- 不把时间戳、随机数写进提示词。

`discuss` 只有在作者明确要求（`now`）时才整轮发言；召唤师只是预测"该讨论"时，仍然一次一位、走停顿闸门。

### 2026-11-10 深夜：自说自话

截图里鸠摩罗什连着插了八段、还在回应自己上一句。第一版处理是"把引用全删掉"，但那会让他忘记自己刚说过什么；
现在的做法是**把上下文拆成带标签的三块**，让他自己判断：

- 【作者先前写的】——作者之前的正文
- 【你们在屋里说过的】——引用行，明确标成"你们自己的话，只作背景，不要当成他说的"
- 【作者刚刚说的这一句】——本次口述的那一段（focus），只有这一段是要回应的

提示词要求他先判断"这一句接的是哪个话题点"（回应你、新问题、还是往下讲），再接住那个点；
不要另起话题，也不要接自己的上一句。另加两道闸：`now` 一轮 20 秒冷却；强制回答也要有新内容（≥8 字），
除非作者点名。

## 最终形态：召唤师判断，正文引用

- **两秒静默才开口**：转写完成时不说话；从最后一次出声算起，安静满 2 秒才把这一轮交给召唤师。
  作者还在说、或者转写还没回来，谁都不出声。同一句引用不会重复插入。
- **在座与发言分开**：计划里 `seat` 是这一轮所有在座的人，`speak` 才是这一轮真正开口的人（通常一位）。
  房间取**并集**——之前坐下的不会因为召唤师没重复列出就消失，只有 `dismiss` 才会请走。
  召唤师回答「在，他在」时，必须同时把那个人放进 `speak`，让他当场开口，不能只报个到。
- **取消/保存会作废在途的回答**：页面关闭时递增 generation，已经发出但还没回来的插话/计划不会落进新页面。
- **刚点名请来的人先开口**，原来在座的人让一轮。
- **空转写不算失败**：咳嗽、噪声、半截音不再弹「没有识别出文字」；每段静音 800ms（原 500ms）才提交，
  给识别器多一点上下文。
- **保存 / 取消会结束语音**：点任一个都会停麦并清空状态条，不会留在页面上。
- **召唤师回答问题，不道歉**：禁止「我没接住」这类句式；「可以找谁」先报名字再让人开口，
  「进来了吗」直接答在/不在；它还看得到自己上一轮说过什么，避免重复同一句调度。
- **召唤师一直在场**：麦克风一开，每说完一句、每停顿一次都先经过他。他判断作者是在写东西、
  在跟他说话、在对某位客人说话，还是在让客人之间对话。
- **他也会说话**：作者跟他说话时 `mode=host`，他的回答以 `> **召唤师**：…` 写进正文；
  让客人讨论时 `mode=discuss`，他可以说一句开场，再给客人写互相接话的差事。
- **面板不做语义判断**：没有关键词表、没有名字模糊匹配。是不是在叫谁、是不是在提问、名字被听错成什么样，
  全部交给召唤师读上下文判断；面板只执行计划（一次停顿最多一条、不在原文没变时重复回答）。
- **没有字数门槛**：只要有内容就交给召唤师，由它决定这一轮要不要人。
- **点名 → 一定有人出来说**；没点名但判断得出来 → 也派一位；判断不出来 → `keep`（维持房间、这轮不出声）。
- **客人说的话只写在正文里**（`> **名字**：内容`）；语音条只显示状态（在听/识别中/召唤师在看这一桌/在座），
  不显示任何一句"像人说的话"。被点名但没有可补充的，仍会用自己的人设开场白说一句引用。

## 成本与风险

- 每次停顿 1 次调度调用（system 稳定，命中前缀缓存）+ 0–3 次插话；插话仍受 45s/220 字/句末三道闸。
- `discuss` 整轮只在作者要求时发生（最多 3 次插话），预测性讨论仍是一人一句。
- 每位客人有自己的间隔（45s 起，被忽略后 ×1.6，最多 180s），且全局 25s 不连发。
- 自动造人：召唤师点名才造，10 分钟限流。
